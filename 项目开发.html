①
Scrum Master 职责 – 护航流程、排除障碍、推动自组织、促进沟通、引导回顾

用户故事 & 故事点估算

标准格式

“作为 <角色>，我想要 <活动>，以便于 <价值>”

例：作为已注册用户，我希望重置密码，以便找回账号

INVEST 原则

独立·可协商·有价值·可估算·小而可测

故事点参考（斐波那契）

1(极简) / 2(简单) / 3(中等) / 5(复杂) / 8(极复杂)
例：重置密码 ≈ 5点

Gitee 功能分支协作流程

1
创建分支：git checkout -b feature/xxx (基于最新 master)
2
日常提交前拉取：git pull origin feature/xxx 避免冲突
3
推送 & 发起 PR → Gitee 新建 Pull Request，指定审查者
4
审查 → 修改 → 合并 (管理员合并后删除分支)
5
保护分支：master 设为“禁止直接推送”，强制 PR 流程
# 核心命令速记
git checkout master && git pull
git checkout -b feature/login
git add . && git commit -m "feat: login"
git push origin feature/login
# Gitee 网页 → 创建 Pull Request

项目管理：看板 + 里程碑

任务看板 (Kanban)

状态列：待处理 / 进行中 / 已完成
拖拽更新，每日站会同步进度，透明化冲刺进展。

里程碑 (Milestone)

每个 Sprint 创建一个里程碑，将关联的Issue/任务移入里程碑，追踪迭代完成度。
Sprint结束及时关闭里程碑。

评分系统

小组作品得分 40%

功能完整性14′ · 代码质量10′ · 数据库设计6′ · 前端体验6′ · 演示4′

甲方满意度 20%

需求匹配度10′ · 用户体验5′ · 创新/附加功能5′

每周总结得分 15%

共4周，每周3.75分（看板/Backlog/Review/回顾材料）

个人得分

✅ 小组公共基础分 = 作品40 + 甲方20 + 每周总结15 = 75分。
✅ 个人贡献系数 = 教师评分(30%) + 小组互评(70%)加权归一化，系数范围0.7~1.3。
✅ 个人最终得分 = 小组公共基础分 × 个人贡献系数。
📌 多劳多得，防止“搭便车”。

第12周具体任务（下课前必须完成）

  • 1. 创建 Gitee 账号 — 每位同学注册 Gitee 账号，完善个人信息（用户名、邮箱）。
  • 2. 组长创建仓库并邀请成员 — 组长新建私有仓库，在「管理」→「仓库成员管理」中邀请组员（角色：开发者）和教师（角色：报告者）。
  • 3. 用户故事 + 优先级排序 — 编写条用户故事，使用 P0/P1/P2 标记优先级（P0最高），形成 Product Backlog，并在仓库的 Issue 或看板中记录。
  • 4. 完成里程碑 & Sprint 1 看板设置 — 创建里程碑「Sprint 1」，截止日期为第13周开始前；看板设置三列（待处理/进行中/已完成），将 Sprint 1 任务卡片拖入“待处理”。
  • 5. 基础框架代码提交 — 初始化 Flask 项目（包结构、工厂函数、蓝本、基础模型），推送到仓库 main 分支。
